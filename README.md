# Logic progression ayno

Онлайн-курс развития мышления: **1637 задач** в пяти направлениях —
логическое, стратегическое, аналитическое и эмоциональное мышление (25 тем
на 5 уровнях сложности, от «Разминки» до «Эксперта») и академические
способности: 13 школьных предметов с разделением по классам с 7 по 11.
К каждой задаче есть подсказка и пошаговый разбор.

## Что внутри

- **Главная страница** — описание курса, программа, уровни, вопросы и ответы,
  демо-задача прямо на первом экране.
- **Курс** — пять направлений, у каждого своя страница (`#/c/logic`,
  `#/c/strategy`, `#/c/analytics`, `#/c/emotional`, `#/c/academic`) со своими темами,
  тренировкой, тестом уровня, задачей дня, статистикой (опыт, решённые
  задачи, точность, дни занятий, прогресс по уровням и темам, карта
  активности) и достижениями. В каждой
  теме есть короткая теория, разобранный пример и задачи пяти уровней.
  Следующий уровень темы открывается, когда решена половина задач
  предыдущего. Все направления устроены одинаково.
- **Школа** (`#/c/academic`, «Академические способности») — алгебра, геометрия,
  физика, химия, биология, информатика, русский язык, литература, английский
  язык, история, обществознание, география и основы безопасности. Пять
  ступеней здесь — это классы: 1 → 7 класс, …, 5 → 11 класс. Теста уровня нет:
  ученик выбирает свой класс на странице направления, и к нему подстраиваются
  «Продолжить», задачи и теория в предмете, тренировка и задача дня. Все
  классы открыты сразу — можно повторить прошлые или забежать вперёд. Теория
  предмета разбита по классам: в каждом разделе — главное из программы года.
- **Тест уровня** — у каждого направления свой: 15 задач (по 3 на уровень).
  По результату открываются подходящие уровни во всех темах этого направления.
- **Тренировка** — два режима:
  - **Новые задачи** — сайт сам создаёт задачи прямо в браузере и никогда не
    повторяет ни уже показанные, ни задачи курса. Можно решать без ограничения.
    Уровень сложности человек выбирает сам — любой из пяти, без открытия в
    курсе, — и может сменить его прямо во время тренировки;
  - **Задачи из курса** — случайная подборка по уровню и темам (только
    открытые уровни).
  Сначала выбирается направление, затем уровень и темы.
  В каждой теме (кроме «Нестандартных задач») есть кнопка «Новые задачи», а на
  странице курса — кнопки уровней 1–5 для быстрого старта.
- **Задача дня** — одна и та же для всех в течение дня.
- **Прогресс** — опыт (XP) и ранги, серия дней, карта активности,
  статистика по направлениям, уровням и темам, достижения, выгрузка и загрузка прогресса,
  светлая и тёмная тема.
- **Анимации** — плавная смена страниц, блоки появляются при прокрутке,
  числа и полосы прогресса «дорастают», верный ответ отмечается конфетти и
  улетающим «+XP», новый ранг — всплывающим уведомлением, логотип
  «рисуется» при загрузке. Если в системе включено «Уменьшить движение»,
  анимации отключаются (`src/components/Motion.tsx`).

Регистрация не обязательна: без входа прогресс хранится в `localStorage`
браузера. Если подключить Supabase (см. ниже), появляются **вход и
регистрация**: прогресс хранится в облаке и одинаков на компьютере и телефоне.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # сборка в dist/
npm run preview    # просмотр сборки
```

Сайт статический, адреса страниц — через `#` (например, `/#/course`), поэтому
его можно разместить на любом хостинге без настройки сервера.

**Vercel.** Импортируйте этот репозиторий в Vercel — настройки менять не нужно:
Vercel сам определит Vite, команду `npm run build` и папку `dist`.

## Аккаунты и синхронизация между устройствами

Кнопка «Войти» есть на сайте всегда. Пока хранилище аккаунтов не подключено,
страница входа объясняет посетителям, что прогресс хранится в браузере, а
владельцу — как включить вход.

**Самый простой способ — интеграция Supabase в Vercel:**

1. В проекте сайта на vercel.com откройте **Storage → Create Database →
   Supabase**, выберите бесплатный план и создайте базу.
2. Подключите её к проекту (**Connect Project**). Vercel сам добавит ключи
   (`SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`,
   `POSTGRES_URL_NON_POOLING` и другие).
3. **Deployments → последняя сборка → ⋯ → Redeploy.**

Остальное сайт делает сам:

- при сборке `scripts/setup-db.mjs` применяет `supabase/schema.sql` — создаёт
  таблицу `logic_progress`, правила доступа «каждый видит только своё» и
  мгновенные обновления (скрипт можно запускать повторно);
- регистрация идёт через функцию `api/register.js`: аккаунт создаётся сразу
  подтверждённым, поэтому письма не нужны. Встроенная почта Supabase без
  своего SMTP-сервера отправляет письма только участникам команды проекта, так
  что без этой функции посетители не смогли бы подтвердить email;
- в сайт попадают только адрес проекта и публичный ключ; сервисный ключ
  используется только на сервере.

«Забыли пароль?» отправляет письмо, поэтому для всех посетителей сброс
пароля заработает после подключения своей почты в Supabase
(**Authentication → Emails → SMTP Settings**).

**Вручную (любой хостинг):** создайте проект на supabase.com, выполните
`supabase/schema.sql` в **SQL Editor**, задайте `VITE_SUPABASE_URL` и
`VITE_SUPABASE_ANON_KEY` (локально — в `.env.local`) и пересоберите сайт. На
хостинге без серверных функций регистрация идёт обычным способом, с письмом;
отключить подтверждение можно в **Authentication → Sign In / Providers → Email
→ Confirm email**.

Как это работает:

- Войти можно на странице `#/account` (кнопка «Войти» в шапке). Там же —
  регистрация, «Забыли пароль?», смена имени и выход.
- При входе прогресс с этого устройства **объединяется** с прогрессом в
  аккаунте, а не заменяется: решённые задачи с обеих сторон сохраняются,
  опыт пересчитывается по ним (`src/lib/merge.ts`).
- Каждое сохранение устроено как «скачать → объединить → записать», поэтому
  одно устройство не затирает решения другого (`src/lib/cloudSync.ts`).
  Изменения с других устройств приходят сразу, а также при возвращении на
  вкладку.
- При выходе прогресс остаётся в аккаунте, а с устройства стирается.

## Как устроены задания

Задания не написаны вручную по одному — их создают генераторы в
`src/generators/*.ts`. Они работают двумя способами:

1. **Банк курса.** Скрипт `npm run tasks` один раз создаёт 1576 заданий и
   сохраняет их в `src/content/tasks.json` вместе с 61 задачей, написанной
   вручную.
2. **Новые задачи в браузере.** В режиме «Новые задачи» те же генераторы
   работают на сайте, в фоновом потоке (Web Worker, `src/generators/worker.ts`),
   чтобы страница не подвисала. У каждого задания есть отпечаток содержания
   (53-битный хеш); отпечатки показанных заданий хранятся в прогрессе, поэтому
   задача не повторится — ни среди новых, ни среди задач курса.

Всего — больше 55 000 разных задач. В эмоциональном направлении ситуации
написаны вручную (их нельзя надёжно «собрать» из случайных чисел), поэтому
большая часть вариантов уже входит в банк курса и новых задач там немного.
То же в школьных вопросах на знание фактов (литература, правила русского
языка, первая помощь): расчётные задачи — алгебра, геометрия, физика,
стехиометрия, генетика, системы счисления, даты — создаются почти без
ограничений. Если в выбранных темах и на выбранном
уровне варианты всё-таки закончатся, сайт так и скажет и предложит выбрать
другой уровень или другие темы.
Банк курса детерминированный: при одном и том же коде получаются те же задания
с теми же `id`, поэтому сохранённый прогресс не ломается.

Правильность ответов проверяется при генерации:

- **силлогизмы** — перебором всех диаграмм Эйлера–Венна; объяснения строятся
  как цепочка выводов или как пример-контрпример;
- **рыцари и лжецы**, **порядок**, **логические таблицы** — перебором всех
  вариантов; берутся только задачи с единственным решением;
- **ряды, аналогии, матрицы, «лишнее»** — ответ сверяется с библиотекой
  похожих правил, чтобы у задачи не было второго правдоподобного ответа;
- **нестандартные задачи** (`src/generators/classic.ts`) написаны вручную;
- **игры** — полным разбором позиций (выигрышные и проигрышные), «Ним» — через
  двоичную сумму; в вариантах ответа ровно один выигрышный ход;
- **планирование** — расчётом ранних сроков, запаса времени и критического
  пути; «какое дело ускорить» проверяется пересчётом срока;
- **выгодные решения** — точным расчётом, наборы при ограниченном бюджете —
  перебором всех наборов; берутся только задачи, где простые «жадные» правила
  ошибаются;
- **ходы наперёд** — максимин, доминирование и равновесие Нэша проверяются по
  всей таблице, выбираются только задачи с единственным ответом;
- **анализ** — ответы вычисляются по сгенерированным данным; неверные варианты
  в вероятности — типичные ошибки (сложение вместо умножения, «с возвращением»
  вместо «без» и т. п.);
- **эмоциональное мышление** — ситуации и объяснения написаны вручную и
  опираются на устоявшиеся модели: колесо эмоций Плутчика, различие вины и
  стыда, переосмысление и паузу при сильных эмоциях, «я-сообщения», активное
  слушание, типы ответа на хорошие новости. Неверные варианты подобраны так,
  чтобы не допускать второго толкования;
- **школьные предметы** — в расчётных задачах ответ вычисляется (корни,
  прогрессии, производная, площади и объёмы, законы физики с g = 10 м/с²,
  молярные массы и расчёт по уравнению реакции, скрещивания перебором гамет,
  правило Чаргаффа, переводы систем счисления, объём информации, даты и
  хронологический порядок); степени окисления сверяются с таблицей известных
  значений. Вопросы на знание (произведения и авторы, правила, ударения из
  словника ФИПИ, первая помощь) собраны в таблицы; неверные варианты берутся
  из той же таблицы, а близкие по смыслу (например, «повесть» и «рассказ»)
  не ставятся рядом, чтобы не было спорных ответов.

После изменения генераторов пересоберите банк:

```bash
npm run tasks
```

Скрипт выводит число заданий по темам и уровням и останавливается с ошибкой,
если найдёт повтор `id`, ответ не из списка вариантов, повтор вариантов и т. п.
Посмотреть задания одной темы в терминале:

```bash
node --experimental-strip-types --no-warnings scripts/show.ts syllogisms 3
```

Пересчитать ёмкость генераторов (можно указать одну тему):

```bash
LIMIT=500 node --experimental-strip-types --no-warnings scripts/capacity.ts
```

## Структура

```
scripts/
  generate-tasks.ts   сборка и проверка банка заданий
  capacity.ts         сколько разных задач умеет создавать каждая тема
src/
  generators/         генераторы по темам, фоновый поток для новых задач
  content/            банк заданий, направления, темы с теорией, уровни и ранги
  pages/              главная, курс, тема, задача, тренировка, тест, прогресс
  components/         карточка задачи, шапка, общие элементы
  store/progress.ts   прогресс, опыт, открытие уровней, достижения
  store/auth.ts       вход, регистрация, сброс пароля
  lib/                роутер, проверка ответов, новые задачи, синхронизация,
                      объединение прогресса, даты, тема
supabase/schema.sql   таблица и правила доступа для аккаунтов
```
